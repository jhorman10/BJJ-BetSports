# backend-deps-hygiene Specification

## Purpose

Eliminate dead dependencies, fix version drift between requirements files, extract development tooling from production requirements, correct misleading comments, and update CI workflows to install dev tooling from a separate requirements-dev.txt. No behavior changes — pure configuration refactor.

## Requirements

### Requirement: Dead dependencies removed

`orjson` MUST be removed from `backend/requirements.txt` (line 33) and `backend/requirements-worker.txt` (line 28). `scipy==1.13.1` MUST be removed from `backend/requirements-worker.txt` (line 5). `recharts ^3.6.0` MUST be removed from `frontend/package.json` (dependencies). After removal, no module MAY import or reference these packages.

#### Scenario: orjson absent

- GIVEN the change applied
- WHEN `pip install -r backend/requirements.txt` and `pip install -r backend/requirements-worker.txt` complete
- THEN `orjson` is not installed, and no Python import of `orjson` exists in the codebase

#### Scenario: scipy absent

- GIVEN the change applied
- WHEN `pip install -r backend/requirements-worker.txt` completes
- THEN `scipy` is not installed, and no Python import of `scipy` exists in the codebase

#### Scenario: recharts absent

- GIVEN the change applied
- WHEN `npm install` runs in frontend/
- THEN `recharts` is not listed in dependencies, and no import of `recharts` exists in `frontend/src`

### Requirement: Development dependencies extracted

A new file `backend/requirements-dev.txt` MUST be created containing exactly: `pytest>=8.0.0`, `ruff>=0.1.0`, `black>=23.0.0`, `isort>=5.12.0`, `flake8>=6.0.0`, `mypy>=1.8.0`, `types-pytz>=2023.3`. All seven packages MUST be REMOVED from `backend/requirements.txt`. After the change, `backend/requirements.txt` MUST contain only runtime dependencies.

#### Scenario: Dev file created and used

- GIVEN `backend/requirements-dev.txt` exists with the seven packages
- WHEN `pip install -r backend/requirements-dev.txt` completes
- THEN all seven tools are available in the environment

#### Scenario: Requirements.txt cleaned

- GIVEN the change applied
- WHEN `pip install -r backend/requirements.txt` completes
- THEN none of `pytest`, `ruff`, `black`, `isort`, `flake8`, `mypy`, `types-pytz` are installed
- AND all remaining packages are runtime dependencies

### Requirement: Version drift resolved

`backend/requirements.txt` and `backend/requirements-worker.txt` MUST declare identical versions for shared dependencies. Pinned versions MUST be:

- `pydantic==2.12.5` (both files)
- `pydantic-settings==2.12.0` (both files)
- `httpx==0.26.0` (both files)
- `aiohttp==3.13.2` (both files — worker currently 3.9.5, bumped to main)
- `python-dotenv==1.0.0` (both files)

#### Scenario: Identical versions

- GIVEN both requirements files
- WHEN compared for shared packages
- THEN every shared package declares the exact same version string

#### Scenario: Worker upgraded safely

- GIVEN worker requirements upgraded (aiohttp 3.9.5 → 3.13.2, pydantic 2.7.4 → 2.12.5, etc.)
- WHEN the worker service starts and processes training jobs
- THEN no runtime errors occur from version mismatch (exploration confirmed safe)

### Requirement: motor pinned

`motor` MUST be pinned to an exact version in both requirements files. The version MUST match the current resolved version in `backend/requirements.txt` (currently `motor>=3.2.0` — resolve to `motor==3.6.0` or the latest compatible 3.x).

#### Scenario: Exact pin

- GIVEN `backend/requirements.txt` and `backend/requirements-worker.txt`
- WHEN inspected for `motor`
- THEN both declare `motor==X.Y.Z` (no range, no bare name)

### Requirement: Stale comments corrected

The comment block in both requirements files claiming "numpy, joblib, scikit-learn, scipy, pandas removed" MUST be corrected. `numpy==1.26.4`, `joblib==1.4.2`, `scikit-learn==1.5.0`, `pandas==2.2.2` are still declared AND used. The comment MUST be removed or updated to reflect reality.

#### Scenario: Comments match reality

- GIVEN the updated requirements files
- WHEN read by a developer
- THEN no package marked "removed" is still declared in the file

### Requirement: Frontend recharts removed and lockfile regenerated

`recharts` MUST be removed from `frontend/package.json` (dependencies). `frontend/package-lock.json` MUST be regenerated by running `npm install` (or `npm ci` after removal) to reflect the removal.

#### Scenario: Recharts gone

- GIVEN `frontend/package.json` after change
- WHEN `npm install` runs
- THEN `recharts` is absent from `dependencies`, `package-lock.json` is updated, and `npm ls recharts` returns empty

### Requirement: CI workflows updated

GitHub Actions workflows `.github/workflows/ci.yml`, `.github/workflows/ci-pr.yml`, and `.github/workflows/lint.yml` MUST be updated to install development dependencies from `backend/requirements-dev.txt` instead of `backend/requirements.txt` for lint/type-check steps. Runtime steps (if any) MUST continue using `backend/requirements.txt`.

#### Scenario: Lint jobs use dev file

- GIVEN the updated workflows
- WHEN the lint/type-check jobs run
- THEN `pip install -r backend/requirements-dev.txt` is invoked (or equivalent)
- AND jobs complete successfully

#### Scenario: Runtime uses base file

- GIVEN the updated workflows
- WHEN a runtime or test step runs
- THEN `pip install -r backend/requirements.txt` is used (no dev tooling installed)

## Non-Goals

- Dockerfile split (separate change)
- CI workflow consolidation (separate change)
- Bun migration (abandoned — plan doc will be deleted separately)
- datetime.utcnow migration (separate change B)
- Orphaned `backend/Dockerfile` deletion (part of Docker split)

## Verification

All requirements are testable via:
- `pip install -r backend/requirements.txt` → no dev tools, no dead deps
- `pip install -r backend/requirements-worker.txt` → same versions, no dead deps
- `pip install -r backend/requirements-dev.txt` → 7 dev tools present
- `npm install` in frontend/ → no recharts, lockfile updated
- CI lint/type-check jobs pass on all three workflows
- `grep -r "orjson\|scipy\|recharts" --include="*.py" --include="*.tsx" backend/ frontend/src/` → no matches (except git history)

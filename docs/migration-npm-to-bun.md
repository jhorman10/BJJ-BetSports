# Migration Plan: npm → Bun

## Overview

Migrate the project's frontend package management from npm to Bun. Bun is already installed on this machine (v1.3.14). This migration covers the frontend workspace only; the backend remains Python-based and is unaffected.

## Goals

- Replace npm with Bun as the frontend package manager
- Replace `package-lock.json` with `bun.lockb`
- Update all CI/CD pipelines, Docker configs, scripts, and documentation
- Maintain full parity in dev/build/test workflows

## Scope

### Files to Modify

| `frontend/package-lock.json` | Present | Remove; replaced by `bun.lockb` |

## Step-by-Step Plan

### Phase 1: Local Setup & Verification

1. **Generate `bun.lockb`**
   ```bash
   cd frontend && bun install
   ```
   This creates `bun.lockb` and installs all dependencies using Bun's resolver.

2. **Verify Bun compatibility**
   Run the full frontend toolchain with Bun:
   ```bash
   bun run lint
   bun run build
   bun test
   ```
   Flag any packages that fail under Bun's runtime. Known concerns:
   - `@vitejs/plugin-react-swc` — works with Bun
   - `vitest` — works with Bun
   - `eslint` — works with Bun
   - `vite` — works with Bun
   - `workbox-window` — verify service worker registration works under Bun

3. **Remove `package-lock.json`**
   ```bash
   rm frontend/package-lock.json
   ```

### Phase 2: CI/CD Pipeline Updates

4. **Update `.github/workflows/ci.yml`**
   - Change `cache: npm` → `cache: bun`
   - Change `cache-dependency-path: frontend/package-lock.json` → `frontend/bun.lockb`
   - Change `npm ci` → `bun install`
   - Change `npm run lint` → `bun run lint`
   - Change `npm run build` → `bun run build`
   - Change `npx vitest run` → `bun vitest run`

5. **Update `.github/workflows/ci-pr.yml`**
   - Same changes as Step 4

6. **Update `.github/workflows/lint.yml`**
   - Same changes as Step 4

### Phase 3: Docker & Deployment

7. **Update `Dockerfile.portable`**
   - Change `npm ci` → `bun install`
   - Change `npm run build` → `bun run build`
   - Add Bun installation step if not already present in the base image
   - Update `PATH` to include Bun's binary directory

8. **Update `docker-compose.dev.yml`**
   - Change `npm run dev` → `bun run dev` in the frontend service command

9. **Update `render.yaml`**
   - Change `npm install && npm install vite && npm run build` → `bun install && bun run build`

### Phase 4: Scripts & Tooling

10. **Update `scripts/quality_gate.sh`**
    - Change `require_command "npm"` → `require_command "bun"`
    - Change `npm ci` → `bun install`
    - Change `npm run lint` → `bun run lint`
    - Change `npm run build` → `bun run build`
    - Update `node_modules/.package-lock.json` check → `bun.lockb` check

11. **Update `scripts/validate_and_fix.sh`**
    - Change `npm run lint -- --fix` → `bun run lint -- --fix`
    - Change `command -v npm` checks → `command -v bun` checks
    - Update error messages from "npm" to "bun"

### Phase 5: Documentation

12. **Update `README.md`**
    - Replace all `npm` command references with `bun` equivalents
    - Update installation instructions

13. **Update `CLAUDE.md`**
    - Replace all `npm` command references with `bun` equivalents
    - Update package manager references

14. **Update `.gitignore`**
    - Replace `npm-debug.log*` with `bun-debug.log*`
    - Add `bun.lockb` to the list of files to NOT ignore (it must be committed)
    - Remove `package-lock.json` from `.gitignore` if present (it should be tracked)

### Phase 6: Verification

15. **End-to-end validation**
    - Run `bun install` from clean state
    - Run `bun run lint` — must pass
    - Run `bun run build` — must produce `frontend/dist/`
    - Run `bun test` — must pass
    - Verify `bun.lockb` is committed to git

16. **CI dry-run**
    - Push a branch with all changes
    - Verify all GitHub Actions workflows pass with Bun

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Bun incompatibility with a dependency | Medium | High | Test all frontend commands locally before committing; keep `package-lock.json` in a backup branch for quick rollback |
| CI pipeline breakage | Low | High | Update workflows in a single PR; review Actions logs carefully |
| Docker build failure | Low | Medium | Test `Dockerfile.portable` build locally with Bun installed |
| Render deploy failure | Low | Medium | Render uses `npm install` by default; the `buildCommand` override must be tested |
| `workbox-window` PWA plugin issues | Low | Medium | Verify service worker registration works after migration |

## Rollback Strategy

1. Keep `package-lock.json` in a backup branch (`npm-backup`)
2. All changes are in a single PR — revert the PR if issues arise
3. CI workflows can be toggled back by reverting the workflow file changes
4. Docker and deploy configs can be reverted independently

## Notes

- Bun uses the same `package.json` format as npm — no dependency declaration changes needed
- `bun install` is compatible with npm registry and `package.json` syntax
- Bun's lockfile (`bun.lockb`) is binary and not human-readable; it must be committed to git
- The `bun` command is already available at `~/.bun/bin/bun` (v1.3.14)
- The backend (Python/FastAPI) is unaffected by this migration
